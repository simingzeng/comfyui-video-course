## 1️⃣ 角色一：大画家的脑海（Step1 载入模型组）

在画布最左侧，`Step1 - Load models` 蓝色大框负责把 AI 画画所需的全部大脑与工具包加载进显存：

```text
┌──────────────────────────────────────────────────────────┐
│                   Step1 - Load models                    │
│  ├─ 【UNet加载器】 ➔ z_image_turbo_bf16 (画家扩散主脑)   │
│  ├─ 【加载CLIP】   ➔ qwen_3_4b (阿里 3.4B 中文语言大脑)  │
│  └─ 【加载VAE】    ➔ ae.safetensors (图像编解码暗房工具) │
└──────────────────────────────────────────────────────────┘
```

### 1. `UNet加载器`：画家大脑与数据类型
* **`unet_name`**：选择扩散主模型。本课使用的是 `z_image_turbo_bf16.safetensors`（6B 极速写实模型，保存在 `models/diffusion_models/`）。
* **`数据类型 (weight_dtype)`**：默认选 `default` 或 `bf16`（现代 RTX 40/50 系显卡支持原生 BF16 精度，出图既快又清晰）。

### 2. `加载CLIP`：中文语言翻译官
* **`类型 (type)`**：选 `lumina2`（基于 Qwen 大模型打造的国产前沿生图架构）。
* **`CLIP名称`**：若左侧连着浅绿线，**按住绿线向外一甩拔掉断开**，即可看到里面选中的正是阿里开源的：👉 **`qwen_3_4b`**！
* **💡 为什么以前必须用英文，而现在能直接打中文？**：
  * **老一代 AI (SD 1.5 / SDXL)**：使用的是 OpenAI 纯英文训练的 `CLIP-L`，输入中文会乱码，逼着大家背英文词；
  * **新一代国产旗舰 (Z-Image-Turbo / Lumina 2)**：直接把 **通义千问 (Qwen 3.4B)** 搬来作为文本中枢！原生深度理解中文成语、复杂句式、写实光影与物理材质，**无需任何翻译，直接打中文即可一键精准出图**！

### 3. `加载VAE`：图像编解码器
* **`vae_name`**：选择 `ae.safetensors`，负责最后把抽象潜空间还原为人类可见的 PNG 图片。

| 🟡 **黄色** | `CONDITIONING` | **翻译官指令**（提示词） | ➔ 只能连入采样器的 `positive` / `negative` 接口 |
| 🌸 **粉色/品红** | `LATENT` | **未显影抽象画布** | ➔ `空白画布` ➔ `采样器` ➔ `VAE解码器` 的 `samples` |

## 2️⃣ 角色二：需求翻译官（Step3 提示词中枢）

在画布中央，负责将人类意图转化为画家指令的神经中枢：

```text
【CLIP 文本编码 (正向词)】 ──(黄色条件线)────────────────────────────> 【K 采样器: 正面条件】
【CLIP 文本编码 (正向词)】 ──(黄色条件线)──> 【条件零化】 ──(清零负向)──> 【K 采样器: 负面条件】
```

### 1. `CLIP 文本编码`：输入中文写实光影提示词
点击黑色大框内部，按 `Ctrl + A` 全选清空，替换填入以下带有电影写实质感的中文提示词：
```text
一只身穿精细机械外骨骼铠甲的白猫，坐在雨后赛博朋克街道上，路灯与水坑霓虹灯倒影，写实照片，电影级光影，8k解像度
```

### 2. `条件零化 (ConditioningZeroOut)`：负向条件静音器
* **为什么插在下方？**
  * 传统 SD 1.5/SDXL 作画时，采样器每一步都需要同时计算正向词与负向词（差分引导），耗时翻倍；
  * 而 Z-Image-Turbo / FLUX 等现代极速蒸馏模型收敛能力极强，**完全不需要写冗余的负向提示词**；
  * `条件零化` 节点将负向条件数学归零注入 K 采样器的 `负面条件` 接口，使采样器省去一半的负向计算量，全速输出高质感画面！

## 3️⃣ 角色三：画纸与画布（Step2 图像尺寸）

在画布左下角，`空Latent图像 (SD3)` 节点负责设定画框尺寸与并发生成策略：

```text
┌──────────────────────────────────────────────────────────┐
│                   空Latent图像 (SD3)                     │
│  ├─ 宽度 (width)       ➔ 1344 (或 1536)                  │
│  ├─ 高度 (height)      ➔ 576 (标准 21:9 电影画幅)        │
│  └─ 批量大小 (batch)   ➔ 1 (单次并发生成几张)            │
└──────────────────────────────────────────────────────────┘
```

### 1. 宽与高（电影画幅与比例调校）
* **动手实操**：
  1. 若 `宽度` / `高度` 左侧连着浅绿线，**按住绿线向外一甩拔掉断开**；
  2. 双击数字，将 `宽度` 改为 **`1344`**，`高度` 改为 **`576`**（或 `1536 × 640`），打破默认的正方形构图！

::: details 📐 工业级避坑：为什么 AI 绘图分辨率必须是 64 的倍数？主流画幅速查表

在 AI 生成中，**分辨率千万不能随意输入奇数或非 64 整除的数字**：
* **原理**：VAE 解码器在潜空间中进行 **8 倍降采样**，而现代 DiT 架构又以 **$2 	imes 2$ 的 Patch** 为计算单元，必须同时满足 $8 	imes 8 = 64$ 的整除倍数，否则画面边缘极易出现色斑断层或报错！

| 影视画幅 | 严谨比例 | 推荐标准分辨率 (64的整数倍) | 适用场景与视觉感受 |
| :---: | :---: | :---: | :---: |
| 🎬 **正统 21:9 宽屏** | **$2.33:1$** | **`1344 × 576`** ($64	imes21 : 64	imes9$) | 严格等比 21:9，带鱼屏满屏震撼视野 |
| 🎥 **好莱坞宽银幕** | **$2.39:1$** | **`1536 × 640`** ($64	imes24 : 64	imes10$) | CinemaScope 院线级变形宽银幕电影感 |
| 📺 **标准 16:9 横屏** | **$1.78:1$** | **`1344 × 768`** / **`1024 × 576`** | 常用 B 站、YouTube 与电视横屏标准 |
| 📱 **竖屏 9:16 短视频** | **$0.56:1$** | **`768 × 1344`** / **`576 × 1024`** | 抖音、TikTok、视频号短视频 |
| 🔲 **正方形 1:1 头像** | **$1.00:1$** | **`1024 × 1024`** | 社交头像与主体特写展示 |

:::

### 2. 批量大小 (`batch_size`)：并发一锅出 vs 队列排队跑
* **机制对比**：`批量大小` 是显卡同时并发画多张（速度极快但显存成倍暴涨）；右上角的 `任务队列` 是一张接一张排队跑（显存完全不变，零风险）。
* **硬件建议**：旗舰卡 (RTX 5080/4090) 跑 Turbo 时可设为 `2` 或 `4` 极速出图；主流卡 (RTX 4070 12GB) 建议保持 `1`。

::: details 🚨 避坑核心：为什么视频时代严禁调大【批量大小】？{open}

* **静态图**：画 1 张图显卡只计算 **1 帧**画面（显存仅占 7~10GB），批量设为 4 时显存翻倍（14~16GB），5080/4090 还能吃得消。
* **AI 视频 (Wan 2.2)**：一条 5 秒 @ 24fps 的视频，是由 **121 帧（121 张连续大图）+ 时序运动** 组成的巨大张量！当 `批量大小 = 1` 时，显卡已经在同时计算这 121 帧，显存已满载（12GB~15GB）。
* **若把批量改成 2**：等于命令显卡**同时并发计算 2 条完整视频（$121 	imes 2 = 242$ 帧）**，显存需求直接暴涨到 **30GB+**，哪怕 24GB 的 4090 也会**瞬间发生 CUDA OOM 爆显存直接崩溃黑屏**！
* 💡 **正确做法**：想批量生成多条视频，必须保持 `批量大小 = 1`，通过右上角的 **`任务队列 (Queue)` 排队逐条生成**！

:::

## 4️⃣ 角色四：画笔作画中枢（K 采样器 + AuraFlow 配件）

在画布右侧，`K 采样器` 是最核心的去噪作画引擎，由前置算法配件与 5 大核心参数共同调控：

```text
【UNet 加载器】 ──(模型紫线)──> 【采样算法 (AuraFlow)】 ──(优化后模型)──> 【K 采样器】
```

### 1. `采样算法 (AuraFlow)`：前置算法调校配件
* **`移位 (Shift 3.00)` 的作用**：Z-Image-Turbo 采用了现代 **Flow Matching（流匹配）** 算法。`移位 3.00` 负责调校去噪早期与晚期的注意力分配，让画面在短短 8 步内噪点消除得极其干净、写实质感极其强烈。

### 2. `K 采样器 (KSampler)` 核心参数逐一拆解：

```text
┌───────────────────────────────────────────────────────────┐
│                    K 采样器 (KSampler)                    │
│  ├─ 种子 (seed)               ➔ 8888 (画面的基因灵感)    │
│  ├─ 生成后控制 (control)      ➔ fixed (锁定/随机策略)    │
│  ├─ 步数 (steps)              ➔ 8 (去噪雕琢轮数)         │
│  ├─ cfg                       ➔ 1.0 (听话程度与引导尺度) │
│  ├─ 采样器名称 (sampler_name) ➔ res_multistep (画笔算法) │
│  ├─ 调度器 (scheduler)        ➔ simple (步长节奏曲线)    │
│  └─ 降噪 (denoise)            ➔ 1.00 (从零作画/垫图重绘) │
└───────────────────────────────────────────────────────────┘
```

1. **`种子 (seed)` 与 4 种控制策略**：
   * **大白话**：Seed 是画面的**“基因灵感编号”**。只要 Seed 固定，人物长相、五官构图、机位角度与光线朝向就会 **100% 锁定不变**！
   * **策略分类**：
     * **`fixed`（固定）**：死死锁定数字。专用于**微调局部词汇、固定角色长相与多镜头一致性**。
     * **`randomize`（随机）**：每次运行自动抽奖换新数字。用于寻找全新灵感。
     * **`increment` / `decrement`**：每次运行数字自动 `+1` / `-1`。
   * **动手实操**：拔掉 `种子` 左侧绿线，填入 **`8888`**，控制菜单切换为 **`fixed`**！
2. **`步数 (steps)`**：画家的雕琢轮数。Z-Image-Turbo / FLUX 极速模型仅需 **8 步**（或 4 步）即可极速收敛；传统 SDXL 则需 25~30 步。
3. **`cfg`**：画家的听话程度。极速流匹配/蒸馏模型中**必须固定设为 `1.0`**；传统模型通常为 6.0~8.0。
4. **`采样器 (Sampler)` 与 `调度器 (Scheduler)`**：
   * **`采样器 (Sampler)` = 画家的【运笔技法 / 手法算法】**：`res_multistep`（多步重启，Z-Image 官方钦定👑，4~8步综合推算不产生色斑）；`euler`（欧拉，FLUX 首选🚀）；`dpmpp_2m`（SDXL 经典万金油）。
   * **`调度器 (Scheduler)` = 画家的【作画节奏表 / 计划】**：`simple`（匀速线性，流匹配标配⭐）；`karras`（前快后慢，SDXL 细节之王）。
5. **`降噪 (denoise)`**：`1.00` 代表 100% 从零开始全新作画（文生图）；若设为 `0.30~0.70` 则为垫图重绘（图生图）。

::: details 🎯 两大阵营闭眼搭配公式

* **⚡ 现代极速流匹配阵营 (Z-Image-Turbo / FLUX / Wan 2.2)**：
  👉 采样器选 **`res_multistep`** 或 **`euler`**，调度器**死死锁定 `simple`**！
* **🏛️ 经典传统扩散阵营 (SDXL / SD 1.5)**：
  👉 采样器选 **`dpmpp_2m`**，调度器选 **`karras`**！
* ❌ **切忌乱搭**：不要给极速流匹配模型套用复杂的 `karras` 或高阶求解器，否则极易导致画面过曝、过度锐化或噪点残留。

:::

## 5️⃣ 角色五：暗房显影师与装裱相框（Step4 显影与保存）

在画布最右侧，负责最后的视觉呈现与物理落地保存：

```text
【K 采样器 (粉色潜空间)】 ──(samples)──> 【VAE 解码】 ──(蓝色图像线)──> 【保存图像 (Save Image)】
【加载VAE (红色药水)】 ──(vae)─────────┘
```

1. **`VAE解码`**：将潜空间抽象数学矩阵，解密还原成**人类肉眼看得懂的真彩色 RGB 像素**。
2. **`保存图像 (Save Image)`**：将成品大片实时渲染在画布上，同时自动按日期持久化保存在硬盘的 `D:\ComfyUI-Installs\MainEnv\ComfyUI\output\` 目录中！
